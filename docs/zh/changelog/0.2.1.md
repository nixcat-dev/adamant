# 0.2.1

[English](../../changelog/0.2.1.md)

2026-11-03。取自 `main`。从源码构建：[构建](../building.md)。`.basalt` 格式不变。本发布改变了另一台机器上的客户端可以指代哪些图像：请先读[升级](#升级)。

## 亮点

- 图像来源随请求的来处而定。来自本机的请求可以指代任意路径或 URL，无需任何配置。来自其他任何地方的请求得到 `data:` URL，外加 `--image-url-host` 点名的 host 和 `--image-dir` 点名的目录。服务器过去会为任何客户端抓取任何 URL、读取任何路径。[图像来源](../configuration/image-sources.md)（设计：@giveen）
- 质量对照全精度衡量：原始模型的 llama.cpp BF16 参考。在同一份 Q8_0 权重上，Basalt 得 KLD 0.0200，llama.cpp 得 0.0325。NVFP4 提示词路径的 4-bit 激活——标准关卡触及不到的部分——现在在长提示词上也做了测量：2K token 提示词上约 0.002 KLD，8K 上尚无定论，换来 17 到 19% 更快的 prefill。[质量](../precision/quality.md)
- 一个 `Qwen3.8-FN-NVFP4-DQ8` pack 在 Hugging Face 上加入默认的 `-DQ6_K`：相同的 NVFP4 专家配 Q8_0 dense 投影，KLD 更低（0.0561 对 0.0624），prose 上约慢 7%。[单项成本](../precision/isolated-costs.md)

## 升级

1. 重新构建：[构建](../building.md)。
2. 另一台机器上以 URL 或路径指代图像的客户端，在其 host 或目录被放行之前会得到 400，或者它改发 `data:` URL。本机上通过 LAN 地址或主机名、或经由转发代理访问服务器的客户端，都算作另一台机器。
3. 所有客户端：一张图至多 32 MiB、64 megapixels，`data:` URL 必须是 base64，EPS、ICO 和 JPEG 2000 被拒绝。
4. 在同一台机器上、不添加转发头的代理或网关之后，设置 `--image-remote-only`：否则这类代理的客户端会被算作本机。
5. `basalt-bench --community` 拒绝含空格、或超过 40 个字符的提交者名字，与结果行的检查一致。

## 近期变更

2026-11-01 至 2026-11-03 的变更。

### 新增

- `--image-url-host`、`--image-dir`、`--image-remote-only`（见上文）。
- `--expert-profile FILE` 指明启动时放置的 profile，已安装的引擎因此不再依赖其源码树（@xyehya）。
- 在 `tool_choice` auto 下与 tools 一起发送的 JSON 格式：回答是工具调用或该 JSON 值；此前返回 400。
- bench 的 JSON 报告 VRAM 层的命中率（@giveen）。
- 双卡和四卡 RTX 5080（@Hazelhof）以及 RTX 5080 IQ3_S（@Cosmin-Local-Ai）的社区条目。

### 提速

commit 级别的改进，不是基准测试结果。

- 长提示词的 KV 把从主卡移出的专家交给对等卡，在单流请求上经提示词分割的借用量完成。
- 两阶段 Q6_K 输出头跳过其选取会被丢弃的行（@xyehya）。
- 惰性 L2 预取还会带上下一层的 FFN 读取矩阵（@kaushikvira、@xyehya）。
- CPU 专家行：IQ3_S 与 IQ2_S 网格索引用 AVX-VNNI，IQ4_NL down 与 Q2_0（@xyehya）；NVFP4 用 AVX-VNNI-INT8 和 5 到 8 的单遍宽度（@giveen）。
- URL 抓取与图像解码在请求回合之外运行，缓慢的来源不再拖住其他请求。

### 变更

- 输出可能改变。两阶段 Q6_K 输出头为其列界限之上的每一行重新评分：贪心文本曾取决于验证窗口宽度，且 `--spec` 取 7 和 8 时与 1 到 6 的结果不同（@xyehya）。SM 数低于 160 时，至多八行的窗口运行 mid 链，于是一行的最后几位不再取决于窗口宽度（@xyehya）。提示词的 CPU 分担按缓存的表来取专家，因此同一提示词在同一组锁定层上会把同样的专家交给 CPU（@xyehya）。[精度](../precision/index.md)
- 没有停顿读数时（Windows），低于 RAM guard 的 RAM 只在持续 10 s 后才算危急。
- 存储会话的文件夹和文件在 Linux 上仅属主可访问（@xyehya）。
- 层分割设备检查的错误以 `CUDAn:` 开头。
- 移除任何途径都到不了的代码：远程专家层、其放置与归约选项及 kernel，以及 decode 循环的非链式尾部（@xyehya）。

### 修复

- 两块卡都满载时，缓存的副本无法页锁定（WSL 下的 Linux、原生 Windows）时，decode 在几个 token 后停滞（@G-3-N-O）。
- 回复的最后一个窗口不提交最后一个已发送 token 之后的行，于是一次聊天续写不会再回退到旧检查点或完整重读（@xyehya）。
- 参数为 `oneOf` 或 `anyOf` 联合的工具现在能拿到其参数（@hagudelom）。被引号包在字符串参数内的工具调用文本留在字符串里（@giveen）。
- `--open` 在模型就绪后才打开页面，加载失败则完全不打开。
- 修掉一个优化 CUDA 构建中的错误字节读取：从打包值中取字节一律改为移位，适用于所有格式。
- zero-doorbell 图上的批处理窗口只走一次交接，`--parallel 2` 及以上不再在第 0 层超时（@beastrobin）。
- release 会立即结束有界的设备等待；release 失败后结束的引擎跳过会无限等待的 CUDA 拆卸。
- 分割查询 gate 的回退路径会等待 gate（@xyehya）。RAM 归属报告按净节省计数（@xyehya）。
- Windows 上按 `basalt-vision.exe` 查找 vision sidecar（@f1zz1ec0ke）。
- 最后一个 pair 的分词合并不再在带范围检查的构建上中止。
- 缺失的专家 profile 会连同查找所用路径一起点名。
- 格式错误的 `data:` URL 或非对象的 Anthropic `source` 不再使处理程序崩溃。
- bench JSON 与启动行中的版本号与发布版本一致。
