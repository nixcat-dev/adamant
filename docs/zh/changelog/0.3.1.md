# 0.3.1

[English](../../changelog/0.3.1.md)

2026-11-08。Basalt 的发布，合并进本分支；这里只列出本分支会构建的路径。从源码构建：[构建](../building.md)。请先读[升级](#升级)：有几个标志变化。`.basalt` 格式仍是版本 2；`experts.layout` v7 是一个 section 版本。

## 要点

- 对等卡共用一条提示词路径（`prefill::PeerShare`）：对等卡从排好的分组缓冲计算它那部分专家的提示词行，用主卡的格式与激活，然后把行送回。Ada 上的验证待做。
- 新增 pack：Flash-Next `UD-IQ1_S`（某一层的 gate 与 up 行类型不同，`experts.layout` v7）与 `UD-IQ4_XS`；Q5_K 与 Q6_K 专家层加入 glue 路径（#264），IQ4_XS 的 gate/up 行也是（#272，@michmill1970）；Q2_K 与 Q3_K 专家在所有路径上都能跑。
- 模型文件照原样读取：不再往 `~/.cache/basalt` 解包任何内容。引擎的 `--vision` 在引擎内编码，`--vision-external` 接收 sidecar 的嵌入。
- `--kv-resident` 与 `--batch`、`--parallel` 一起可用：每个槽位流送自己的 K/V（#186，@f1zz1ec0ke）。
- 一份 RAM 保留量（`--ram-reserve-mib`）与一个服务的 RAM 守卫，并且 SSD 上的专家处处可见。
- `--max-payload-mib` 设置最大请求体。

## 升级

1. 重新构建：[构建](../building.md)。
2. **`--peer-prefill-rows N` 移除了。** `--no-peer-prefill`（配置键 `no-peer-prefill: true`）关掉对等卡的提示词份额；不开时它生效。
3. **引擎的 `--vision-mmproj PATH` 移除了。** 引擎接受 `--vision`（在引擎内编码，取自 pack 的 `vision/mmproj`）或 `--vision-external`。服务器的 `--vision dynamic|cpu|N` 不变，并自行转传这些标志。
4. **带 `experts.layout` v7 的 pack 需要 0.3.1。** 目前只有 `UD-IQ1_S` 有；更早的引擎会拒绝它并给出更新提示。其他 pack 依旧能在更早的引擎上运行。
5. **存在磁盘上的会话会落空一次**：缓存键随 vision 标志改变了。
6. **`--ram-reserve-mib`（默认 2048）取代原来的 RAM 下限**，`--ram-reserve-mib 0` 关闭守卫。[内存下限](../running.md#内存下限)
7. `~/.cache/basalt/<id>` 只保留 `engine.log` 与会话缓存；早先的 `tokenizer/` 目录和 `vision/mmproj.gguf`（Flash-Next 是 886 MiB）可以删除。

## 内存、启动与服务

- **SSD 上的专家处处说明。** 任何只有文件持有的专家会给出一条引擎警告：`N experts on SSD (X GiB) · free X GiB RAM`，以及该
  模型的其他提示。服务器控制台重复它，`/metrics` 带上 `engine.spill`（`experts`、`total`、`bytes`；没有溢出时为 `null`）和每个
  请求的 `ssd_share`，统计页面在存在 SSD 层时把 Experts 块变为琥珀色。[内存下限](../running.md#内存下限)
- **一份 RAM 保留量。** `--ram-reserve-mib`（默认 2048）是留给系统其余部分的空闲 RAM；旧的下限（RAM 的百分比、固定的后期
  内存量、文件缓存最小值）都移除了。提示词和图像的 host 缓冲先分配，RAM 层随后取得空闲 RAM 减去保留量和驱动页跟踪之后的
  部分，所以某一处短缺不再把整层的专家送到文件里。第二卡与文件读取的提示词环形缓冲改为有上限，而不是随留在文件里的专家
  增长；提示词也不再为整块 staging 嵌入和 Engram 行。RAM 副本先分配它的 checkpoint 块并占住页锁定提示词缓冲的 RAM，再据此
  定容；它对后续占用的估算移除了。[内存下限](../running.md#内存下限)
- **一个 RAM 守卫。** 服务的 RAM 守卫在共享的 serve 路径里运行并守住保留量，因此每个模型都以同样方式停放会话、挂起新请求
  并在 RAM 危急时停止一个。`--ram-reserve-mib 0` 关闭它，适用于它停止过本来放得下的请求的机器。[内存下限](../running.md#内存下限)
- **默认上下文 8,192。** Flash-Next 原来是 4,096；仍可用 `--max-context` 设置。[模型](../models/index.md)
- **启动行。** 每个条目的行显示引擎将运行的 drafting（`spec=N`）；共享的空闲睡眠只在共享行上说一次；会话目录行只在
  `--debug` 下显示；加载读作 `loading MODEL (N waiting)`，换模型读作 `swap OLD -> NEW (N waiting)`。
- **`--max-payload-mib` 设置最大请求体。** 服务器默认最多读取 256 MiB；更大的请求体得到 413 并指出上限。
  [配置](../configuration/index.md)

## Flash-Next

- **Pack：** `UD-IQ1_S` 按原样转换（某一层有 IQ2_S 的 gate 与 IQ2_XXS 的 up 行），`UD-IQ4_XS` 已发布在 Hugging Face；Unsloth 的
  `UD-IQ1_M`、`UD-IQ2_XS` 与 `UD-IQ3_XXS` pack 也加入已发布集合。[Flash-Next](../models/qwen38-flash-next.md)
- **专家：** Q5_0 的 down 层跑在 MMQ 预填充与设备规划尾段上；Q2_K 与 Q3_K 的 tile、分组 kernel 与 CPU 点积；IQ4_XS 与
  Q5_K/Q6_K 的 gate/up 行加入 glue kernel。
- **`--no-peer-prefill`** 取代 `--peer-prefill-rows`；对等卡的提示词份额走共享的 `prefill::PeerShare` 路径。
  [Ada](../precision/ada.md)

## 修复

- 引擎死掉时按它的退出码或信号以及最后一条错误行报告，而不是猜测原因。
- 引擎协议行整行写出，因此进度行不会再落进 token 行里。
- 一次启动正在进行时 `/metrics` 保留上一次的上下文；统计页面显示单个槽位的上下文。
- 路由停止或服务器关闭时遥测线程随之停止。
- 带图像的请求不再把图像的 base64 当作字面标签来扫描。
- 自动行把驻留量命名为 `ram-experts`；`--model` 与配置文件同用时说明它不受支持。

## 已核对

在改动代码的那些提交上、用 Basalt 的硬件跑过；同样的路径在 Ada 上的测量仍是开放项
（[Ada](../precision/ada.md)）：

- kernel 改动：贪心输出与改动前的构建逐位一致（冻结层、400 token、struct 与 prose）。
- `UD-IQ1_S`，100 个 chunk，int8 KV：通过 decode 路径对照 BF16 参考测量（[方法](../precision/quality.md)）。
- Flash-Next NVFP4 配合共享对等路径：贪心输出一致，对等层钉住。
- `prefill::PeerShare` 与混合 gate/up 层应当与它们取代的路径逐位相等；它们的 parity 检查覆盖的是字节，而不是 Ada 的 kernel。
