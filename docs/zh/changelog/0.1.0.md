# 0.1.0

[English](../../changelog/0.1.0.md)

2026-10-29。首个带标签的发布，取自 `main`。从源码构建：[构建](../building.md)。

## 亮点

- 会话落盘：停放的会话在重启、崩溃或闲置卸载后恢复；一个 10 万 token 的会话在重启后约 0.5 s 回来，而不是 10 s 的重读（400 W 的 5090 配 180 W 的 5060 Ti）。[运行](../running.md)
- 就地休眠：`--idle-sleep` 在请求之间释放 VRAM，下一个请求约 4 s 唤醒模型，而不是 40.6 s 的冷加载（同样的卡与功耗限制）。[运行](../running.md)
- 统计页：一个视图，含 GPUs 侧栏、Speed、Slots 和 Logs。[运行](../running.md)
- 语法默认开启：工具调用和 JSON schema 在解码期间强制执行。[精度](../precision/qwen38-flash-next.md)
- 原生 Windows x64 移植，每个 pull request 在 CI 中构建并做 CPU 测试。[平台](../platforms.md)
- `basalt-probe`：测量机器和冷启动 decode 速度，并给出建议设置。[probe](../probe.md)

## 0.1.0 时的 Basalt

- 模型：Qwen3.8-Flash-Next，一个 `.basalt` 文件包含权重、分词器、MTP drafter、专家 profile 和 vision projector。pack：NVFP4、UD-Q4_K_XL、UD-Q5_K_XL、UD-Q6_K_XL、Q8_0、GSQ-RCO IQ3_S、IQ3_XXS 和 Q2_0。[模型文件](../model-file.md)
- 硬件：NVIDIA Blackwell（sm_120）配 CUDA 13，支持 Linux 和 Windows x64。[平台](../platforms.md)
- API：OpenAI 与 Anthropic 兼容（chat、messages、responses、count_tokens）、工具调用、JSON schema 输出、Web UI 和统计页。[配置](../configuration/index.md)
- 专家层：没进 VRAM 的专家存放在系统 RAM，可选常驻；自适应层随会话推进把热门专家移入 VRAM。[专家缓存](../configuration/index.md#专家缓存与内存)
- 对等卡：一个 `gpu` 设置选卡；主卡之后的每块卡都是专家层（最多三个）。[GPU](../configuration/gpus.md)
- MTP drafting：pack 自带的 drafter 每窗口提议至多 8 个 token；除非开启 relaxed drafting，输出与朴素 decode 相同。[投机解码](../configuration/index.md#投机解码-mtp)、[精度](../precision/qwen38-flash-next.md)
- 语法：来自 llama.cpp 的 GBNF 与 JSON schema 语法，默认开启，按验证窗口强制执行。[精度](../precision/qwen38-flash-next.md)
- 视觉：经 pack 自带 projector 的图像输入，可在引擎内、sidecar 卡上或 CPU 上运行。[运行](../running.md)
- 并行槽位：`--parallel N` 同时服务至多 8 个请求。[运行](../running.md)
- 会话缓存：RAM 中的检查点，落盘停放的会话在重启后恢复。[运行](../running.md)
- 就地休眠：`--idle-sleep` 在请求之间交还 VRAM 并保留进程。[运行](../running.md)
- 提示词路径：长提示词跨卡读取；prefill 在计算之下流式载入专家。[GPU](../configuration/gpus.md#跨卡读取长提示词)
- 自动设置：留空的设置在启动时选定并打印一行。[配置](../configuration/index.md#自动设置)
- basalt-probe：测量机器和冷启动 decode 速度，并给出建议值。[probe](../probe.md)
- 质量：经 decode 路径对照 Q8_0 的 PPL 与 KLD。[精度](../precision/index.md)
- 社区实测：用户在一个预设上的 benchmark 行。[社区实测](../community.md)

## 近期变更

2026-10-15 至 2026-10-29 的变更。

### 新增

- `--idle-sleep`：模型在请求之间就地休眠，在下一个请求上唤醒（Linux）。
- 会话落盘：`--conversation-cache-disk-mib` 停放会话，并在重启或崩溃后恢复。
- 启动时放置上一次运行经 `--expert-profile-save` 保存的专家。
- 三块及以上相同的卡：长提示词默认跨卡读取。最多三个专家层。
- 至多 16384 token 的提示词在其他槽位 decode 的同时单独读取；各槽位通过彼此的检查点共享某个提示词的开头。
- `basalt-probe`：测量机器并给出建议设置。
- 语法：GBNF 引擎、llama.cpp 的 JSON-schema 转换器和工具调用语法；Anthropic `output_config.format` 会发送语法；每个批处理槽位持有自己的语法。
- 工具调用参数按其声明的 schema 解码。
- 分词器改为 C++，服务器把渲染后的提示词文本发给引擎。
- `reasoning-budget-tokens` 设定默认思考预算；`answer-room` 为思考之后的答案预留输出空间。
- 控制台日志：每个事件一行紧凑的 `key=value`；加载进度在非终端环境下以忙碌心跳和 MB/s 显示。
- 统计页：一个视图，含 GPU 侧栏、Speed、Slots 和 Logs；`/metrics` 提供逐卡和逐槽位的历史、队列和最佳请求。
- Windows：原生 x64 移植，每个 pull request 在 CI 中构建并做 CPU 测试。
- GitHub Pages 上的社区实测页；新增 RTX 5090、RTX 5080（WSL2）、RTX 5060 Ti 和 RTX PRO 4000 配置的条目。

### 提速

数字见 commit message 和[精度](../precision/index.md)。此处的任何数字都不是基准测试结果。

- Decode：当 combine 等待 CPU 或对等层时，下一层的权重读入 L2；首个提交之后的 GDN 层在下一个窗口内部提交；shared expert 与被路由链并行运行。
- 在更快的对等卡上 decode：当模型定价认为有收益时，它接管每个 GDN 层的关键 head 和输出头的一份。
- Pool：更细的行列范围任务、每层一个批次、AVX2 i-quant 行中的 AVX-VNNI；停放的 worker 短暂自旋后让出核心。AVX-512 i-quant 行用 pdep 构造符号掩码，并 gather IQ3_S 与 IQ2_S 网格（比特不变）。
- Prefill：短分块用 16 个一组的 FP4 专家、注意力期间复制下一层可能的专家、长提示词用较短的首块。
- 长提示词：跨主卡和每个专家层卡读取。
- 被采样的行在一次启动内完成选取；前 8192 行 token embedding 也驻留 VRAM。
- `qsa`：五到八个查询的窗口把其块当作两行四个来评分。
- Q6_K gate/up 专家跑在各自的 decode 和 prefill kernel 上（prefill 用 MMQ kernel）；Q8_0 dense 投影跑在张量核心 kernel 和 mid 链上。

### 变更

- `gpu` 是唯一的选卡设置。移除：`--peer-device`、`--peer-slots`、`--layer-split`、`--split-device`、`--split-skip-if-fits`、`--batch-groups`、`--expert-cache-device1` 到 `3`，以及依赖它们的 stage 与 remote 选项。不再选择层分割。
- 引擎中还移除：`--spec-min-p`（自适应草稿规则始终开启）、`--spec-split`、`--no-spec-split`、`--coupled-draft`、`--no-coupled-draft`、`--pcie-frac`、`--pcie-mode`、`--expert-cache-remote-placement`、`--remote-expert-opt`、`--expert-cache-per-layer`、`--expert-cache-cpu-order`、`--trim-stage-weights`、`--sync-every-layer`、`--stream-token`、`--shared-late`、`--ple-sync-submit`、`--no-ple-prefetch`、`--no-host-worker`、`--no-prefill-borrow`、`--no-split-rows`、`--no-hit-poke`、`--no-token-graph`、`--no-publish-kernel`、`--no-fast-attn`、`--no-fast-select`、`--no-fused-gdn`、`--no-fused-gr`、`--gr-fp32-activations`、`--gr-native-mmvf`、`--cpu-oracle-q8-0`、`--native-*` 系列开关（`bf16`、`bf16-extra`、`flash-attn-short`、`gdn`、`moe-combine`、`ple-key`、`ple-postops`、`qsa`、`qsa-indexer`、`rope`、`router`），以及诊断项 `--dump-logits`、`--dump-layers`、`--dump-halves`、`--check-logits`、`--logits-stride`。其中每一个要么被强制开启、要么从未被读取、要么选择的是旧代码路径；默认路径不变。
- `vision` 取 `off`、`dynamic`、`cpu` 或一个 GPU 编号；`on` 和 `peer` 被拒绝。
- `spec` 在有 drafter 时默认为 8（原为 7）。贪心输出不变；带 seed 的采样请求可能返回不同的文本。
- 默认值：`prefill` auto；pack 带专家 profile 时专家常驻；单卡服务器每窗口自适应一次。
- 语法默认开启，由 `response_format` 选用；`--no-grammar` 关闭。提示词式、事后校验的 JSON 路径、其 `structured_output_failed` 错误和 `jsonschema` 依赖一并移除。
- 请求必须指名被服务的模型（alias 或文件名）；名称未知或缺失返回 404。
- 工具名严格按原文读取。
- CPU pool 的 worker 和宿主线程不再固定到单个核心；`--pool-affinity` 只决定用哪些核心来划定 pool 规模。
- 到对等卡的提示词路径只走宿主中转；直接访问路径已移除。
- 模型缓存目录不再由环境变量设定；`--native` 和 `--pack` 已移除。
- 存储的会话绑定格式版本而非引擎版本，因此只要格式不变，新构建就能恢复旧构建写入的内容。更早构建写入的文件只恢复一次。
- 超过 64 megapixels 的图像在解码前被拒绝。
- 在混合架构 CPU 上，`pool-affinity auto` 把 E 核的一半加入 pool。

### 修复

- Windows：引擎窗口处于后台时仍保持全速。
- Windows：把 working-set 最小值设为硬限制，从而可以锁定专家表。
- 可空字符串型的工具参数接受原始文本；schema 模式中的原始控制字节以 `\xNN` 转义进入语法。
- 弹性 KV 不再把专家缓存压到低于一个提示词分块的借用量；放不下的请求被拒绝，而不是致命错误。
- 带 profile 的缓存槽位按 256 字节对齐的大小计量。
- 提示词路径的借出上限在 RAM 补集被锁定后读取锁定份额。
- 实时 tok/s 在高于 128 tok/s 时保持其 2 s 窗口，而不是退回均值。
- 在单流与槽位之间迁移的请求报告其真实的提示词读取时间。
- 向 RAM 复制专家失败时，先同步再释放其归属。
- `avx_bench` 在没有 AVX-512 的 CPU 上跳过 AVX-512 行。
- MSVC：CUDA 目标以 `/Zc:preprocessor` 构建；NVFP4 CPU 专家行避免聚合体拷贝。
