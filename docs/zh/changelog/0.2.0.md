# 0.2.0

[English](../../changelog/0.2.0.md)

2026-11-01。取自 `main`。从源码构建：[构建](../building.md)。本发布更改了 `.basalt` 文件格式：请先读[升级](#升级)。

## 亮点

- `.basalt` 文件格式版本 2。引擎要求版本 2 的 pack，并拒绝版本 1 的 pack，提示信息会点名 `tools/migrations/basalt_v1_to_v2.py`。权重相同，输出完全一致。版本 2 的 pack 已在 Hugging Face 上；你已有的版本 1 pack 可以在本地迁移，无需下载、无需重新量化。专家 profile 现在随引擎发布（`data/profiles`），int8 hyper-connection 表存储在 pack 中，于是每次启动省去约 0.5 s 的工作。[文件格式变更日志](../basalt-file-changelog.md)、[模型文件](../model-file.md)
- Decode 速度，冷启动，RTX 5090（400 W）配 RTX 5060 Ti（180 W），NVFP4 pack，对照 0.1.0 时的 `main`：约 +13%。仅 prose 从 297 到约 330-337 tok/s；完整 bench 顺序下 prose 从 277 到约 296 tok/s；struct 从 558 到约 600 tok/s。全部保持精确：贪心输出完全一致。具体手段：
  - 更便宜的 draft head 筛选：draft head 经由一份 2-bit 副本筛查其行，再从主输出头读取精确行；
  - 精确的两阶段输出头：Q8_0 输出头以位平面运行，对只读列表头部的请求保留精确的 top K，[两阶段输出头](../precision/two-stage-head.md)；
  - 与第二块卡共享的输出头筛选，当它比主卡慢时；
  - 更好的起始专家放置，从多样化的提示词中学得；
  - 更早排序的自适应轮次，在该窗口的最后一层完成后即开始，并在有换入余量时晋升近期大约只被路由过一次的专家；
  - QSA gate 行与注意力并行运行。
- 有损的可选标志：`--route-prior`、`--route-tail-skip` 和 `--relaxed-drafting` 会改变输出。它们默认关闭、从不被自动选中，且带着其中任何一个启动会打印警告。三个 pack 上的质量与 decode 数字：[路由](../precision/routing.md)。
- 思考循环保护：在思考中连续重复同一个 token 256 次的运行会结束思考，然后模型作答。答案部分绝不被监控。`thinking-loop-tokens` 设定次数，`0` 关闭。[采样](../configuration/sampling.md#思考循环)

## 升级

1. 重新构建：[构建](../building.md)。
2. 获取版本 2 的 pack：从 Hugging Face 下载，或用 `python tools/migrations/basalt_v1_to_v2.py` 迁移你手头的版本 1 pack（[migrations](../../../tools/migrations/README.md)）。专家 profile 现在随引擎发布：自定义安装或容器镜像必须把 `data/profiles` 与 `serve/`、`tools/` 放在一起。
3. 已移除且无别名：引擎的 `--dump-hc8`，以及转换器的 `--profile`、`--profile-from` 和 `--hc8`（profile 归引擎所有，hyper-connection 表由转换器计算）。转换器运行产出版本 2 文件。服务器的 `repeat_stop_tokens` 设置及其"重复 token 即按 length 停止"的行为已移除，思考预算里那句生造的收尾提示语也已移除。
4. 采样值超出范围现在返回 400（见"变更"）。

## 近期变更

2026-10-29 至 2026-11-01 的变更。

### 新增

- 上文的两阶段输出头、位平面 Q8_0 输出头和共享输出头筛选；[两阶段输出头](../precision/two-stage-head.md)。
- `--route-prior`、`--route-tail-skip`；relaxed drafting 加入有损标志的启动警告。[路由](../precision/routing.md)
- `thinking-loop-tokens`。
- `--conversation-cache-min-tokens N` 只保留至少 N 个 token 的会话，RAM 与磁盘皆然，使短的辅助请求既不占用槽位也不挤出长会话（@michmill1970）。
- 模型加载期间 Web UI 即上线，显示加载百分比和每块卡的 GiB；模型加载期间到达的请求会等待它，启动加载失败则用 503 回应。
- 空闲会话在旁边的任务运行 15 s 后离开 VRAM，被空闲槽位占去的缓存交还给专家；它们会在接下来的那个槽位中恢复。
- 监听时打印一次地址和各 API，每次加载后打印一行权重信息。
- 惩罚在批处理窗口中生效。
- `basalt-probe` 用单一引擎和一个保存的 profile 尝试自适应层的设置，其报告会给出本次运行的墙钟时间。
- vision sidecar 可以在非 sm_120 的卡上运行，并自行构建（@Yunado）。
- Windows：第二块卡可作为专家层（@hagudelom）。

### 提速

Decode 数字见"亮点"；其余为 commit 级别的改进，不是基准测试结果。

- MTP：一轮的 K/V 追加与其草稿行的 query 投影并行；draft head 从最后一次 mixer 读取开始工作；代理 draft head 按固定顺序保留其重评的行（@xyehya）。
- Verify：PLE 旁支在第 0 层的 mid 链之后分叉；批处理窗口在分割的两阶段输出头旁边于 CUDA0 上运行完整输出头。
- Adapt：只有一张对等卡时，主卡的轮次把全部层放在一起排序；一轮至多晋升 16 个只被路由过一次、位于 CPU 层的专家。
- 在 decode 中的槽位旁边的提示词借用量，会把更早借用中仍被占住的专家从其 RAM 副本移走。
- CPU pool：停放的 worker 在短暂自旋后让出核心，且仅当 pool 的线程数超过物理核心数时。
- 启动：专家缓存填充不再有流水线气泡（@jmgao）。
- 提示词分割可在 KV 流式传输时运行。
- Drafting：草稿头的上下文行保留长提示词中最新缺失的 token，并接收盘子集缺少的目标候选；批处理草稿存储只保留 drafter 读取的 cell。

### 变更

- 采样值原样送达采样器；超出范围的值返回 400 并点名（以前会被收敛或丢弃）。`top_k` 的 0 和 -1 表示不设限制，大于 64 时按所请求的列表采样；`penalty_last_n` 为 0 到 4096；seed 为 0 也是一个 seed。采样默认值来自模型文件的 GGUF 元数据。
- 思考预算用模板自己的结束符结束思考；`answer-room` 保持默认开启。
- 服务器不再因回复重复同一个 token 而终止它；"length" 现在只意味着 `max_tokens`。
- 引擎失败返回 500，不再是 400。图像请求的提示词长于上下文时，在其位置编码确定之前就被拒绝。
- RAM guard 在 RAM 偏低时先丢弃停放的会话并等待，只在 RAM 危急时才停止请求（@xyehya）。
- Linux 上 VRAM 预留下限为 128 MiB，且批处理服务器为缓存之后加载的东西保留空间（@xyehya）。
- 存储的会话保留其系统提示词和最后三个轮次状态；单流会话在另一个槽位有请求进行时保留其草稿 K/V。
- 并行的工具结果按调用 id 排序（@giveen）；生成从提示词位置零开始（@giveen）。
- 某请求排队期间的自适应换入，以及因缺少空闲 RAM 空位而推迟的换入会记入日志（@xyehya）。
- benchmark 检查拒绝含空格的提交者名字。

### 修复

- 有界的设备等待设置中止字，而不是 trap kernel。
- 带小专家 blob 的 pack（Q2_0）可以加载：批量专家读取的暂存缓冲区按直接读取的对齐要求对齐。
- 弹性 KV 按下限的粒度映射，深层请求的 cell 因此能交还；KV arena 的粒度至少为一页（@xyehya）。
- Windows：超过 MAX_PATH 的路径可以打开（@hagudelom）；n-gram 表读取器和 `DirectFile` 可以读取在其他处映射的文件（@f1zz1ec0ke）。
- nvidia-smi 报不出名字的 vision 卡会被报告为它找不到该卡；被分割拒绝的提示词总会说明原因。
- 语法十六进制解析中未初始化的代理对码元。
- 清除引擎与测试中的编译器警告；`WERROR` 覆盖 nvcc，且 CI 在 Linux 上带着它构建。

### 文档与代码

- 文档：`.basalt` 版本 2 布局与文件格式变更日志；带三个 pack 数字的路由标志；采样独立成页；配置参考补上内存、分段和 turn-token 标志，诊断独立成页；带显示器的卡其空闲 VRAM 在多次启动之间会变化，所以要固定 expert cache 才能获得可复现的输出（@hagudelom）。
- 代码：generate 驱动、持久 serve 运行时、提示词处理、MTP drafting 和验证器按行为不变的原则拆分为职责单一的文件（@giveen，#138、#141、#144）。
- 社区实测：RTX 5090 + RTX 5080（@SolettaSolaris）、双 RTX 5090 @ 400 W（@BobbyL2k）、RTX PRO 6000 Blackwell @ 600 W 和 300 W（@beastrobin）、双 RTX 5060 Ti 加内存超频（@azido-azide-azide）、RTX 5090 + RTX 5070 Ti 配 NVFP4 与 Q4_K_XL（@Calogero-Zarbo）。[社区实测](../community.md)
