# 0.3.2

[English](../../changelog/0.3.2.md)

2026-11-08。Basalt 的发布，合并进本分支；这里只列出本分支会构建的路径。从源码构建：[构建](../building.md)。没有标志变化；`.basalt` 格式仍是版本 2。

## 要点

- 干净的 Release 构建快得多：Flash-Next 的 `dec_moe.cu` 被拆开，使对等 kernel 的四个变体可以并行编译；`tools/check_cu_includes.sh` 阻止一个 `.cu` 包含另一个。除这四个变体（ptxas 对它们的调度略有不同）外，GPU 代码相同。Ada 上的耗时与贪心一致性检查待做。
- `tools/package_release.py` 把已构建的目录树打包成 Linux x64 或 Windows x64 归档。归档不含 CUDA 库：需要 CUDA 13 工具包的运行时和 R580 或更新的驱动。[平台](../platforms.md#发布归档)
- 二进制在自己的 `bin/` 文件夹旁边找 data、`serve/` 和 `.venv`，而不是构建时写死的源码路径，因此安装目录可以移动。
- 让专家留在文件里的 RAM 层重新给 OS 文件缓存留一个下限，所以模型装不下的机器在加载时不再把自己换页到失去响应（#285，@tddgit）。[内存下限](../running.md#内存下限)

## 内存、启动与服务

- **文件缓存保有它的下限。** 0.3.1 把每个 RAM 层定为空闲 RAM 减去 `--ram-reserve-mib`，所以模型装不下时，页锁定的层只给文件读取和系统其余部分留下约 2 GiB，加载永远完不成（@tddgit 报告，#285）。让专家留在文件里的层现在也会给文件缓存留下 0.3.1 之前它所需要的量（最大那层的全部专家、一个提示词 chunk 的读取量，至少 4 GiB）；能容纳全部专家的层大小不变，给定的 `--resident-budget-gib` 也不会被削减。启动行会把这个下限算进去。
- **RAM 补充读取容器的上限。** 加载之后它只按 `/proc/meminfo` 定大小，会把专家 pin 到超过 cgroup 上限；现在它与规划和复制使用同一个感知容器的数值。
- **缺少专家 profile 时引擎拒绝启动。** 在安装目录之外运行的二进制找不到 `data/profiles`，会悄悄回退。现在启动在加载权重之前就停止，指出缺少哪个 profile，以及 `data/` 必须在 `bin/` 旁边；`--expert-profile` 仍然替换主 profile。
- **空闲内存查询失败时会说明原因。** 消息里有调用、错误和显卡，而不是之后一个不相干的复制失败（@easonLiangWorldedtech，#289）。
- **Experts 卡片把全部在 VRAM 的盒子显示为全部在 VRAM。** 当每个专家都驻留时，卡片曾停在 "-"；`/metrics` 现在带有 `expert_total`，卡片画出满的 VRAM 条，"All in VRAM"（@beastrobin，#287）。

## Kernel

- **Q6_K 短行** 每个块只暂存一次它们的列。
- **精确的 AVX-512 CPU 专家行**（IQ1_S、IQ2_XXS、IQ2_XS、IQ1_M）对至多四个 token 只解码一次块。
- 两者在数值上都是中性的：相同的求和、相同的顺序。Ada 上的贪心一致性检查待做。

## 发布归档与安装

- `tools/package_release.py` 把 `bin/`、`serve/`、`data/`、`docs/` 以及服务器导入的部分打包成 `basalt-vX.Y.Z-linux-x64.tar.gz` 或 `basalt-vX.Y.Z-windows-x64.zip`。
- `bin/basalt serve` 在归档顶层目录有 `.venv` 时使用它。构建时的源码路径（`BASALT_SOURCE_DIR`）没有了：安装根目录是可执行文件自身所在目录的上一级。
