## 切分改变了什么

当对等卡（`gpu 0,1`）的显存快于主卡时，启动会规划把每个 GDN 层的 mixer（qkv 与 z 投影、
递推、门控 norm、out 投影）按 key head 切分：对等卡承担一个份额，随两张卡的显存带宽而定，
以整个 key head 为单位（至少四分之一，主卡至少保留一个），启动时一行日志说明此事。只有当它
在主卡上省下的 decode 时间超过被其保留挤到 RAM 的专家所值的代价时，才会采用切分（启动时定价
一次；prompt 路径不计价）。在对等卡更慢、也就是常规卡序时不会采用：整个 mixer 留在主卡上，
输出与引入切分之前逐位相同（贪心一致，3 个请求共 1,200 个 token，NVFP4 pack，主卡 400 W、
对等卡 180 W）。以下每项改动只在切分开启时适用。

- **切 K 的 out 投影。** 每张卡把自己那些 value head 的列求和成一个 fp32 部分和；主卡把
  对等卡的部分和加到自己的一份上。一次 fp32 加法取代了单次按 K 顺序的求和，所以结果可能在
  最低位上不同。
- **对等卡上的投影走 dp4a。** 对等卡把 qkv、z 和 out 部分和跑成对 q8_1 行的 dp4a，每 32
  值块内 int32 精确求和，块间求和顺序与主卡 tensor-core kernel 的不同。递推、conv 和门控
  norm 在对等卡的 key head 上运行同样的代码：`gdn_head_split_parity` 对照整层逐位校验每个
  rank 的头。
- **q8_1 scale 步长平局。** out 投影的激活块由 norm 输出量化而来。当两种求和顺序把某个块的
  最大值落在 fp16 舍入平局上时，该块的 scale 会差一个 fp16 步长，而每个 int8 码都一致。
  parity 测试把一步 scale 差与一步数值翻转同样计数，并在更大步长上失败：两种卡序各 60 例
  全部通过，该平局是唯一的 scale 差异。

质量门槛对照 BF16 参考，交换卡序（对等卡 400 W、主卡 180 W），NVFP4 pack，20 个 chunk，
T 3，int8 KV，`--spec 0`，整个 mixer / 切分：PPL 2.3129 / 2.2999，KLD 0.07294 / 0.07262，
top-1 92.94% / 92.96%。按行配对的 KLD 差为 -0.00032 +- 0.0014，5,100 行中有 145 行的
argmax 改变：属于归约顺序噪声（以及切分在对等卡上改变的放置），没有偏移。

长上下文检查，同样的卡序，经 serve 路径贪心（spec 7，int8 KV，每个构建一个全新 engine），
把一篇 200K 文档的前 100,000 与 65,000 个 token 作为裸 prompt，生成 128 个 token。文本很早就
分岔：在第 8 个 token（100K）和第 17 个 token（65K）处，两个构建选出了不同的下一个词，然后
各自以不同的流畅文本继续。该步的前两个 token 在两个构建中都很接近：对领先者施加 -0.1 的
logit bias 会让切分关闭的构建翻转，-0.3 会让切分开启的构建翻转（100K 时两个领先者相差不到
0.1、不到 0.3），65K 时 -0.1 让两者都翻转。所以这次翻转是被求和改变挪动的一次近乎平局，越过
这样的平局之后，两个构建上的贪心文本不可比。
