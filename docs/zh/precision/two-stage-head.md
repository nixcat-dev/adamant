# 两阶段验证头

[English](../../precision/two-stage-head.md)

验证窗口的头对每一列都要读取每个词表行（248,320 行）。两种头分两阶段运行：先对每一行粗筛，只有可能进入
某列前列的行才被精确打分。Q8_0 头按其自身编码的高位粗筛，界有证明，所以每个消费者读的都是精确头的值；
Q6_K 头经一张 2-bit 副本粗筛，尾部保留近似 logits。decode 路径的表在 [index.md](index.md)。

## 精确的位平面 Q8_0 头

Q8_0 头（NVIDIA NVFP4 pack 的那个）在 VRAM 中以位平面保存（q80p.cuh）：每个 2,720 字节的行先放它的 80 个
fp16 block scale，然后对每个编码 u = q + 128 存放其第 2..5 位、第 6..7 位与第 0..1 位，各位平面独立。所有
读取该头的 kernel（窗口的精确遍、token 路径、按映射取的草稿头行及其 2-bit 副本）都把平面读回成 Q8_0 编码，
跑 native_mmvq 的算术：与 Q8_0 行位相同（q80_vhead_parity、q80_proxy_parity）。

在验证窗口中该头分两阶段运行（`q80p_vhead`，q80_vhead.cu）：

1. 粗筛读取每行的缩放因子与第 2..7 位（2,720 字节中的 2,080 个）。令 h = u >> 2、l = u & 3（0..3），一个
   block 的和 q·y 等于 4 Σ h·y + Σ l·y - 128 Σ y，所以把 l 取作 1.5 最多差 1.5 Σ |y|。因此一行的 logit 落在
   c = Σ_b d_w d_x (4 Σ h·y - 126.5 Σ y) 的 w = 1.5 Σ_b d_w d_x Σ|y| 范围内。精确 kernel 的 logit 与粗筛的
   c、w 都是至多 320 项的 fp32 求和，其量级之和至多为 85 w（logit）与 252 w（c），所以它们的舍入不超过 w 的
   1%；粗筛把 w 放宽 1/16 加 1e-6。
2. 每个行块把它每列最大的下界 c - w 记入一个直方图。容纳第 K 大 block 最大值的那个桶的下边缘不高于第 K 大
   的下界（这些最大值分属不同的行），因此也不高于该列第 K 大的精确 logit：即该列的阈值。
3. 上界 c + w 达到阈值的每一行（或不是数值的行）都被精确打分；其余各行保留 c + w，严格低于阈值。

因此，精确 logit 达到第 K 大的每一行都会被打分，其余每一项都严格低于第 K 大的精确 logit：该列最大的 K 项，
按采样器的顺序（先值、后较小 id），就是精确头的 id，顺序相同、fp32 位相同。激活缩放因子非有限的整列被整体
打分，界非有限的行会被打分。K 由请求决定（每个窗口前设置的一个设备字）：贪心取 1，64 项或更少的采样列表取
top_k，其余取 0（每一行精确）。某个 token 的各项不依赖窗口宽度。

| logits 的消费者 | 窗口中的头 | 为什么它读的是精确头的值 |
|---|---|---|
| 贪心选取（argmax，平局取较小 id）；草稿接受比较选取 | 两阶段，K = 1 | 精确的最佳行与值就在该列之中，其余各项都在其下 |
| 1..64 项的采样列表（top_k；服务器默认 20），带 top_p、min_p 与 temperature | 两阶段，K = top_k | 整条链只经由它的 top_k 列表读取 logits：top_p 的归一化、min_p 的基准、temperature softmax 与抽签都在这个列表上进行，而列表里的 id、顺序与值都相同。草稿概率（宽松起草）与保留 id 列表也从同一个列表读取 |
| 超过 64 项的采样列表（top_k 0 或大于 64），单独使用 top_p 或 min_p | 精确遍（K = 0） | 每一行精确 |
| 非中性的 penalty（repeat、frequency、presence） | 精确遍 | penalty 会把行挪过列表边界；中性值不改变任何 logit 的位 |
| `logit_bias` | 精确遍 | bias 可能把任意一行抬进列表 |
| grammar | 两阶段；被拒的行在对窗口做完精确遍之后重新抽样 | mask 可能只剩列表之外的行 |
| 打分的请求（`ppl=`、质量门槛）、logit hash、top-k 日志 | 各行经由 `Verifier::copy_logits` 读取，它先运行精确遍 | 每一行精确 |
| batch 槽位；对等卡快于 CUDA0 时按词表切分头 | 精确遍 | 各槽位用自己的参数采样；两张卡都跑精确 kernel |

在真实验证头输入上每列被精确打分的行数（从 IQ3_S pack 的 bench 样例导出 256 个输入，针对 NVFP4 pack 的头，
全部行）：K = 1：平均 2 行（最多 21）；K = 20：301 行（p99 1,254，最多 1,460）；K = 64：1,214 行（p99
5,234，最多 6,814）。这个界是 2,560 项上的 L1 界，约为粗筛典型误差的 50 倍。参与粗筛的位更少时它会放宽到
不可用（五位：K = 20 时 9.6% 的行），而 2-bit 副本没有可用的界。

冷启动 microbench（q80_vhead_parity，248,320 行，L2 清空，400 W 的 5090），1..8 列时的 µs：改之前的 Q8_0 头
（至多三列用 native_mmvq，四列起用单波 kernel）434 / 438 / 447 / 458 / 463 / 468 / 479 / 479；在位平面上跑
精确遍 447 / 447 / 448 / 455 / 460 / 470 / 481 / 496；K = 20 的两阶段头 338 / 344 / 345 / 348 / 357 / 362 /
370 / 378。粗筛以约 1.5 TB/s 流过每行 2,720 字节中的 2,080 个；为列表中各行打分花 6-15 µs。

在 engine 中（NVFP4 pack，400 W 的 5090 配 180 W 的 5060 Ti 作对等层，冷 prose，对两个构建中文本完全相同的
一条回复做节点 trace，541 个窗口）：头每个窗口花 350 µs（粗筛 332，精确行平均 18），而 Q8_0 头是 439 µs。

层级固定时，两卡与单张 5090 写出的贪心 token 与 Q8_0 头相同（三条 bench prompt，1,200 个 token），带 seed 的
采样回复文本相同（temperature 0.6、top_k 20，prose 与 conv，两个 seed，1,200 个 token），上表每类消费者各一个
请求也得到相同 token（18 个 400-token 请求：贪心、top_k 1、5、20（temperature 1.0）、64、100 与 0、单独
min_p、三组 penalty 与中性值、两个 logit bias、一个 json_object grammar 的采样与贪心、宽松起草）；质量门槛的
5,100 行（20 个 chunk）逐字节相同。

### 较慢对等卡下的拆分

当对等卡的显存比 CUDA0 慢时，窗口的两阶段头按词表切分：CUDA0 粗筛行 [0, r0)，对等卡在它自己那份副本上粗筛
其余行，r0 的取值让两者同时完成（5090 配 5060 Ti 时为 201,984 行与 46,336 行）。两张卡在 pinned 主机内存中
会合：CUDA0 交出窗口的 q8_1 各列与 K，并在粗筛找到某列阈值时立刻发布；对等卡以自己的阈值与 CUDA0 阈值中较
高的一个做粗筛，用同一个 kernel 给达到它的行打分，并列出其中不低于它的所有已打分条目（行号、fp32 位）；
CUDA0 把该列表写进自己的列——那些列中的对等行否则为 -inf。任一侧的阈值都不高于该卡各行中第 K 大的 logit，
因此也不高于该列第 K 大的：该列最大 K 行中的每一行都在自己那张卡上打分，并以精确 kernel 的位被保留或列出
（两张卡跑同一份代码）。一列最大的 K 个条目、它们的顺序和值就是精确头的。K = 0 时，以及每个 batch 窗口中，
CUDA0 的精确遍处理每一行。一张卡等另一张超过自己的时限就给该窗口做标记，窗口连同错误一起被丢弃。

层级固定时，切分写出的贪心 token（三条 bench prompt，1,200 个 token，两卡）与带 seed 的 prose 文本，和只在
CUDA0 上跑该头时相同（q80_vhead_parity 的切分部分：任一卡上 K = 1、20、64、0 的 top-K 列表与抽签都相同）。
在 engine 中（400 W 的 5090、180 W 的 5060 Ti、bench prose seed 101，两个构建文本相同），每个窗口在所有宽度
上都便宜 50-80 µs（三个 token 时 6.65 对 6.71 ms）。

## Q6_K 头的近似尾部

Q6_K 输出头（IQ3_S pack 的那个）在验证窗口中分两阶段运行（`q6k_vhead`，q6k_head.cu）。248,320 行中的每一行
都由一张 2-bit 副本（草稿头的拟合，head_proxy.cuh）在 int8 tensor core 上打分，用的正是精确 kernel 所读的
同一批 q8_1 编码。每个行块把它的逐列最大值记入直方图；容纳第 64 大 block 最大值的桶的下边缘不高于该列第
64 大的近似 logit，距它 4 以内的每一行都用 plain Q6_K kernel 的算术精确重打分（位相同）。其余各行保留近似
logits，因此 log 概率保持有限。分块方式不依赖窗口宽度，且无论有多少行符合，高于其列之界的行一律精确重打分，
所以某个 token 的 logits 在任何 T 下位都相同。其选取被丢弃的行可以跳过精确重打分，除非打分或 logit-hash
诊断会读到它们。

它改变了什么：除非副本误差超过裕度，argmax 与采样器的 top-64 列表都来自精确行；重打分行之外的 softmax 尾部
带有副本的误差（rms 约 0.7 个 logit）。采样列表超过 64 项的请求（top_k 0 或大于 64）会读取每一行，所以它的
窗口在同一批列上再跑一遍 plain Q6_K 头（`Verifier::exact_head_rows`）：每个 logit 都精确。

离线，在从 engine 导出的 3,614 个真实验证头输入上（conv、struct、prose 样例），全部 248,320 行，exact = 以
float 计算的 Q6_K x q8_1：

| 样例 | 输入数 | top-64 召回率，margin 4 | margin 6 | margin 8 | 每列重打分行数，margin 4（均值 / p99） | 贪心选取不变 | KLD 精确 -> 两阶段（均值） |
|---|---|---|---|---|---|---|---|
| conv | 1,232 | 99.971% | 100% | 100% | 1,333 / 6,286 | 100% | 4.7e-4 |
| prose | 1,124 | 99.979% | 100% | 100% | 1,098 / 2,988 | 100% | 5.1e-4 |
| struct | 1,258 | 99.968% | 100% | 100% | 1,981 / 12,790 | 100% | 2.5e-5 |

margin 6 与 8 每列分别重打分 5,569-18,649 与 27,962-78,806 行。给副本用最小二乘缩放因子、或按列修正尾部的
偏差，都不能降低 KLD（尾部的质量无偏；代价是它的噪声）。

质量门槛（IQ3_S，100 个 chunk，对照 BF16 基准，层级固定，400 W + 180 W；精确分支同样保留打包好的 2-bit
副本，所以两个分支放置的专家相同）：

| 头 | PPL | KLD 均值 | KLD p99 | 相同 top-1 |
|---|---|---|---|---|
| exact Q6_K | 3.3719 | 0.14744 | 1.6589 | 87.58% |
| two-stage | 3.3804 | 0.14960 | 1.6658 | 87.58% |

两阶段头把 KLD 抬高 0.0022 [0.0018, 0.0025]（1.5%）、PPL 抬高 0.25%：门槛给整个 softmax 打分，包括近似的
尾部。没有一行的 argmax 改变（25,500 行）。层级固定时的贪心解码（`tools/greedy_identity.py`，三条 bench
prompt，900 个 token）与精确头逐 token 相同。
