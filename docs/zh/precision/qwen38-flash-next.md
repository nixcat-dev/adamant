# Qwen3.8-Flash-Next 精度

[English](../../precision/qwen38-flash-next.md)

Flash-Next 在哪里舍入、每种舍入要付出多少代价。方法与参考基准见[质量](quality.md)。导引见
[Flash-Next](../models/qwen38-flash-next.md)。

测试环境：一张 400 W 的 RTX 5090，一张 180 W 的 RTX 5060 Ti 作为对等专家层，128 GB 系统 RAM。每个数字都注明其
构建。几何：隐藏维 2560，4 条超连接流，48 层（36 GDN、12 QSA），512 个专家，top-10。

## 摘要

- **起草不改变输出**，除非设置了 `--relaxed-drafting`。层级固定时，两个被测试的 pack（IQ3_XXS 与 IQ3_S）上
  275 条贪心 prompt 全部 275 条给出相同的 token，并且每个全词表 logit 行都逐位相同。
- **有损标志需显式开启：** `--relaxed-drafting`、`--route-prior`、`--route-tail-skip`。每个都会出现在同一条启动警告里。
- **比 llama.cpp 更接近 BF16。** 同样的 Q8_0 权重，对照 BF16 参考基准：llama.cpp 得 KLD 0.0325、top-1 93.98%；
  Basalt 的 Q8_0 pack 得 KLD 0.0200、top-1 95.34%。
- **只量化一次。** GGUF pack 保留其 block。NVIDIA NVFP4 pack 逐位保留 NVIDIA 的专家码与缩放因子，并把每个稠密
  张量从 BF16 量化一次。
- **默认配置下只有一种舍入带来可测量的质量代价：** Q6_K 稠密投影，对照 NVIDIA 的精度约 0.006 KLD 与 0.3 到 0.6 个
  top-1 百分点。其余一切都约 0.001 或更低。

## 各阶段的舍入

| 阶段 | 格式 | 算术 |
|---|---|---|
| 路由专家（GGUF pack） | 逐字节的 GGUF block；跨层混合类型，也可在一层内混合（UD-IQ1_S：IQ2_S gate、IQ2_XXS up） | q8_1 激活，dp4a 或 int8 mma，fp32 缩放因子 |
| 路由专家（NVFP4） | NVIDIA 的 E2M1 码与 UE4M3 缩放因子，4.5 bit/权重；FP32 尾部 `{s_gate, s_up, s_down}` | q8_1 激活，每 16 值子块精确 int32，fp32 缩放因子；尾部在 fp32 中施加 |
| 稠密投影（attention、GDN qkv/z/out、QSA） | Q8_0（NVFP4 pack 中是 Q6_K；其他 pack 中是 Q4_K/Q5_K/Q6_K） | q8_1 激活，int8 tensor-core 点积，每 32 块精确 int32 |
| Router、GDN alpha/beta、indexer、PLE key/value | 按存储的 BF16 | fp32 激活与求和 |
| 超连接 | int8 副本，每 32 个输入一个 fp16 缩放因子（`hc8`）；hc 读取使用 fp32 激活 | fp32 求和；up 积使用 fp16 高低位 mma |
| Token embedding | GGUF 类型；每个 token 有一行反量化到 fp32 | fp32 |
| 输出头 | Q8_0（NVFP4 pack）或 Q6_K（IQ3_S pack） | verify 中分两阶段，见[输出头](#两阶段验证头) |
| 草稿器 | Q8_0 与 BF16 稠密；专家 Q2_0 常驻 VRAM | 只提出候选；由 verify 决定 |
| KV cache | fp16（默认）、int8（每 64 个值一个 fp16 缩放因子）、q4_0、k8v4 | K/V 反量化到 fp32；分数与 softmax 为 fp32 |
| GDN 状态与卷积历史 | fp32 | fp32 |

decode 的激活在每个量化 matmul 中都取 int8（q8_1）。hc 读取保持 fp32（llama.cpp 把它量化到 Q8_0）。

gather 读取的 n-gram 表就是下载所带的 IQ4_NL 表，除非 `--ple-gguf` 指明另一个 GGUF：这时另有一张 Q8_0 表服务于
gather，于是读取的行是 8-bit 而非 4.5-bit，而 pack 自己的行根本不会被读取。Q5_0 或 BF16 表也可以在那里读取；BF16
行会精确地扩到 f32，所以 gather 得到的就是 checkpoint 自己的值，没有任何表舍入。

### 专家层级

GPU 专家在每个层级上运行同样的 kernel，所以同一个专家在任一张卡上给出同样的位。CPU 专家用 ggml 的 `vec_dot_type`
量化激活（i-quant gate/up 为每 256 值 Q8_K，down 为 Q8_0）。它们把一层路由输出的约 1% 舍入得不同，所以专家坐在哪里
会改变末位。做一致性检查时请固定 `--adapt-swaps 0 --peer-adapt-swaps 0`。

### Prefill

prefill 与 decode 是不同的计算：fp16 与 BF16 GEMM，以及 int8 MMQ。门槛给 decode 路径打分。NVFP4 prompt 专家在任何
chunk 尺寸下都走整数 MMQ（[Ada](ada.md)）。

| 路径 | 格式 | 舍入 |
|---|---|---|
| 稠密投影 | fp16 权重与激活，cuBLAS，fp32 累加 | fp16 激活 |
| 路由专家，MMQ | q8_1 激活，int8 mma | int8 激活舍入（每种 MMQ 格式） |
| 路由专家，NVFP4 | E2M1 码经 16 项 int8 表进入 tile；q8_1 激活，int8 mma，每 16 值子块精确 int32；尾部缩放因子在 SwiGLU 步骤中以 fp32 施加 | int8 激活舍入，与其他 MMQ 格式相同 |
| 路由专家，CPU 池（小于 6,144 token 的 chunk） | ggml 点积，与 decode 的 RAM 层相同 | 上述 CPU 舍入 |
| Attention | int8 KV：q 与 p 取 fp16，一次 fp16 mma，fp32 累加 | 输出与 FP64 参考相差在 1.5e-3 以内 |
| GDN | 分块 delta 规则，每 chunk 16 个 token；状态与门为 fp32；BF16 与 TF32 tensor core | 输出取决于 16-token 网格落在哪里（约 1e-3 相对） |

舍入随分块移动：`--prefill auto` 每个 chunk 至多读 16,384 个 token（NVFP4 为 32,768），K/V 的舍入跟随 chunk 边界。
超过上限的 prompt 先读一个 16,384 token 的 chunk。与解码槽位并行的一次读取取它的 RAM 支撑借额所允许的 chunk（仅当
没有 RAM 副本时封顶在 1,216 个槽位），所以同一段 prompt 的 K/V 末位可能与独占读取不同。CPU 计算流式 prompt 专家中
固定的 0.6 份额。跨卡切分的读取与主卡读取相同：KLD 均值 0.0008（65,535 token）与 0.0005（122,879），两者 top-1 都是
64/64。

实测的 prefill 数字（NVIDIA-checkpoint NVFP4 pack，400 W + 180 W，T 3，int8 KV，除非注明均为 100-chunk 门槛）：

| 测量 | 结果 |
|---|---|
| CPU 份额 0（全 GPU）对 1（全 CPU），NVFP4 DQ6_K，20 个 chunk | PPL 2.3046 / 2.3068，KLD 0.07337 / 0.07085，top-1 93.04% / 93.12%；配对 +0.0025 [-0.0005, +0.0055] |
| K-quant MMQ 对 FP16 路径 | 相对 RMS 1.08e-2 对 5e-4（MMQ 带 int8 激活舍入）；100-chunk 门槛在运行噪声内 |

## 6-bit 稠密投影

NVFP4 pack 的默认 `DQ6_K` 把 attention 的 q/k/v/o、GDN 的 qkv/z/out 与共享专家的 gate/up 存为 Q6_K。`DQ8` 变体把它们
存为 Q8_0。每个张量都从 NVIDIA 的 BF16 量化一次，绝不从 Q8_0 副本量化（那会舍入两次）。

速度，400 W + 180 W，ABBA，每一臂 6 个新进程：

| 测试 | 8-bit 稠密 tok/s | 6-bit 稠密 tok/s | 变化 |
|---|---:|---:|---:|
| prose | 213.4 | 229.9 | +7.8% |
| conversation | 251.0 | 265.1 | +5.6% |
| structured | 420.4 | 463.5 | +10.2% |
| prefill 8K 与 32K | 3,806 与 7,791 | 3,845 与 7,856 | +1% |

质量：见[实测成本](#实测成本)中 Q6_K 对 Q8_0 稠密那一行。

## 起草不改变输出

草稿器提出候选，由 verify 决定。一个窗口用同样的 kernel 运行 T 行（默认 8）。每一行的 logits 与朴素 decode 在任何
宽度下都相等，被拒绝的行不留痕迹。GDN 一层的中段按 `dense_tc_pair`、`dec_gdn_rec`、`dense_tc` 依次运行，其输出也不
依赖窗口宽度。

- **精确性：** 275 条 prompt、256 个贪心 token，`--spec 0` 对 `--spec 7`，层级固定。IQ3_XXS：275 条相同，62,271/62,271
  个 logit 行逐位相同，草稿接受率 69.9%，183.9 到 319.8 tok/s。IQ3_S：275 条相同，60,878/60,878 行，接受率 70.1%，
  145.1 到 239.5 tok/s。prompt 都很短（19 到 395 token）；这是 decode 路径，不是长上下文。
- **强制窗口：** 在 T 1、3 与 7 下教师强制，5,100 个逐行（IQ3_S，20 个 chunk，基准 PPL 2.2883）逐字节相同。
- **采样请求**取自模型的分布，但窗口长度决定每个位置用哪一次随机抽样，所以同一个种子的采样回复在不同窗口宽度下可能不同。
- **Logit bias** 在每一个被验证的行上施加，草稿只有等于带偏置的挑选时才会被接受。取 -100 的偏置永远不会给出该
  token。带偏置的请求接受的草稿更少。
- **嫁接的 MTP 段**保留张量格式、目标权重、目标 hc8 值、词表与专家；转换器用现有量化器重新生成由 MTP 派生的 hc8 项。
  不同的草稿会改变窗口几何，而上面的舍入会在那里改变末位，即使目标张量的字节没有变。对一个嫁接 pack 的简短贪心比较
  与它的来源不同，且没有速度收益；也没有对它跑 BF16 门槛，所以这样的资产不能被当作已验证的生产替代品。

## 请求语法

- **语法**在每个窗口之后检查。第一个被拒绝的 token 在语法掩码下重新抽取，窗口到此结束。prompt 不受约束。工具调用的
  语法从调用开括号开始。带语法的请求关闭宽松起草。

## 宽松起草

采样时，目标概率不低于 P 的草稿会被保留，即使目标自己的抽样本会是另一个 token。在该行输出于是变成贪心：与模型分布
的全变差距离为 1 - p(d)，其余为 0。贪心、`logit_bias`、JSON 格式、质量门槛、batch 槽位与工具名 token 保持精确。

回放，按生成的 token 计（TV = 每 token 的平均全变差；增益 = 每窗口多出的 token）：

| 模型 | 温度 | 精确接受 | P = 0.5 增益 / TV | P = 0.3 增益 / TV | P = 0.2 增益 / TV |
|---|---|---|---|---|---|
| IQ3_S，自然 prompt | 1.0 | 62.3% | +7.1% / 0.042 | +11.9% / 0.072 | +14.7% / 0.089 |
| IQ3_XXS，自然 prompt | 1.0 | 62.9% | +6.6% / 0.043 | +12.1% / 0.073 | +15.2% / 0.089 |

速度，400 W + 180 W，IQ3_XXS，prose 与自然 prompt，温度 1.0，两个种子：精确 332.5 tok/s，P = 0.5 时 366.9
（+10.3%），P = 0.3 时 385.5（+15.9%），P = 0.2 时 399.1（+20.0%）。贪心 struct 不变。

质量，IQ3_S 以温度 1.0、top_p 0.95、top_k 20、关闭思考服务，逐项配对：gsm8k（300 项）精确 0.947，P = 0.5 时
0.973（+0.027 ± 0.020），P = 0.3 时 0.980（+0.033 ± 0.022）；MMLU-Pro（280）精确 0.682，P = 0.5 时 0.714
（+0.032 ± 0.040），P = 0.3 时 0.725。KLD 门槛看不到这一改动，因为它给 logits 打分，而宽松起草改变的是发出哪个 token。
按规则保留的草稿：P = 0.5 时占生成 token 的 3.0%，P = 0.3 时占 5.0%。代价是多样性；这些任务不测量它。

单独的 `--relaxed-drafting` 表示 0.5：代价最小，温度 0.6 时 +5%，1.0 时 +6 到 10%。

## 两阶段验证头

验证窗口对每一列都要读输出头的全部 248,320 行。两个阶段避免整读：

- **Q8_0 头（NVFP4 pack），精确。** 每一行以位平面保存。一次粗筛读取每行的 block 缩放因子与第 2 到 7 位，并用一个
  可证明覆盖该 logit 的区间给每个 logit 定界。上界够到该列第 K 大下界的行被精确打分。每个消费者读的都是精确头的值，
  所以结果按证明是无损的。K 在贪心时为 1，采样的列表不超过 64 时为 `top_k`，其余情况为 0（所有行精确）。真实输入上
  每列的精确行数：K=1 平均 2 行；K=20 为 301；K=64 为 1,214。
- **Q6_K 头（IQ3_S pack），近似尾部。** 每一行由一个 2-bit 副本打分。距第 64 名近似 logit 4 以内的行被精确重打分。
  它们之外的 softmax 尾部带有副本的误差（约 0.7 logit rms）。在 3,614 个真实输入上、余量 4 时，top-64 召回率为
  99.97% 到 99.98%。

代价：Q6_K 头带来 KLD 0.0022 [0.0018, 0.0025]（1.5%）与 PPL 0.25%（IQ3_S，100 个 chunk，400 W + 180 W），
25,500 行上没有 argmax 变化。Q8_0 两阶段头每个窗口 350 us，而 Q8_0 头为 439 us（NVFP4，冷 prose，400 W + 180 W）。
层级固定时，贪心输出与精确头逐 token 相同。

## 两卡之间的 GDN 切分

对等卡快于主卡时，每个 GDN mixer 可以按 key head 切分。切分改变归约顺序，所以输出的末位会变。对照 BF16 参考基准的
质量，交换卡序（对等卡 400 W），NVFP4，20 个 chunk，整个 mixer 对切分：PPL 2.3129 / 2.2999，KLD 0.07294 / 0.07262，
top-1 92.94% / 92.96%。配对 KLD 差异为 -0.00032 ± 0.0014。对等卡更慢时不切分，输出与不切分时逐位相同。

## 有损路由标志

默认关闭，从不被自动选中；这两个标志都需要 device-planned MoE tail。两者对任一 GPU 层持有的专家都生效。

- `--route-prior LAMBDA`（不带值时 0.5）：挑选专家时，就好像 GPU 已持有的专家的路由 logit 都加了 LAMBDA。
- `--route-tail-skip R`（不带值时 9）：当指名某个专家的每一项按权重排序都在 R 或更低时，跳过任何 GPU 都没有的这个专家。

质量门槛（100 个 chunk，400 W + 180 W，int8 KV，两个标志同时开启）与 prose decode：

| Pack | 标志 | PPL | KLD 均值 | top-1 相同率 | prose tok/s |
|---|---|---|---|---:|---:|
| IQ3_S | 关 | 3.382 | 0.1499 | 87.54% | 341.1 |
| IQ3_S | 1.5 / 7 | 3.437 | 0.1828 | 86.55% | 314.1 |
| NVFP4 | 关 | 3.304 | 0.0614 | 91.81% | 281.6 |
| NVFP4 | 1.5 / 7 | 3.616 | 0.2240 | 85.00% | 289.0 |
| NVFP4 | 16 / 1 | 4.422 | 0.4800 | 78.72% | 329.0 |
| Q8_0 | 关 | 3.282 | 0.0197 | 95.39% | 112.4 |
| Q8_0 | 16 / 1 | 8.873 | 1.2338 | 62.26% | 274.9 |

这两个标志的速度来自更少的未命中，所以它随 VRAM 之外专家的份额增长，误差也随之增长。不带值的默认值没有测量。
