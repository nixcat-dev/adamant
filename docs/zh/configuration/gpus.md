# GPU

[English](../../configuration/gpus.md)

一个设置决定用哪些卡：`gpu`。它在服务器里（配置文件 `server` 段的 `"gpu"`，或 `--gpu`）、在 `basalt` 本身、在 `basalt-bench` 和 `basalt-probe` 中含义相同。

| 取值 | 使用的卡 | 主卡 |
| --- | --- | --- |
| 未设置 | 仅 GPU 0；启动时一条警告指出其他可见的卡 | GPU 0 |
| `"0,1"`、`"1,0"` 等 | 正好是这些卡，按此顺序 | 列出的第一张 |
| `"auto"` | 每一块可见的 Ada（sm_89）或 Ampere（sm_86 或 sm_80）卡；其他卡被跳过并用一行指出 | 内存带宽最高的那张，然后 VRAM 最多的那张 |

卡的编号与 `nvidia-smi` 一致。设置 `CUDA_VISIBLE_DEVICES` 时，编号在它的列表内计数（`CUDA_VISIBLE_DEVICES=1,0` 使 `gpu 0`
成为 `nvidia-smi` 称为 1 的那张卡），它的编号也按 `nvidia-smi` 读。编号超出可见卡、同一张卡列了两次、或者某张卡既不是 Ada
（sm_89）也不是 Ampere（sm_86 或 sm_80），都会以错误停止启动。

主卡持有稠密权重、KV 缓存、drafter 和它自己的专家缓存。引擎决定其他卡做什么，并在启动时打印一行，例如
`gpus: RTX 5090 (nvidia-smi 0) main, RTX 5060 Ti (nvidia-smi 1) expert tier`：

- **专家层。** 主卡之后的每张卡持有主卡不持有的专家，在每个 decode 窗口计算它们的行，并像主卡的缓存一样跟随会话。专家按最热
  优先分发，每次给到"按其内存带宽计算至今工作量最少"的那一层，直到每层都装满。两张卡时，一块至少与主卡一样快的第二卡也拿走
  一部分最热的专家，于是两张卡在每层都计算路由专家；更慢的第二卡拿主卡之后的专家。每一层都用主卡的 kernel 计算自己的专家，
  所以专家放在哪里不改变它的行。第二张卡还计算它那些专家在每个提示词块中的份额：与主卡一样快时是任意块，更慢时是 2,559 行
  以内的块（更慢的卡让更长的块付出比它替主卡链路省下的专家更多的代价）。当它的内存比主卡快时，它拿走每个 GDN mixer 和 head 的
  一份（各有一行启动信息；见[两块卡上的 GDN 拆分](../precision/qwen38-flash-next.md#两卡之间的-gdn-切分)）。
- **空闲。** 引擎最多运行三个专家层：第五张及之后的卡保持空闲。

三张及以上卡属于社区测试范围：这里的路径在两张卡上验证过，其中两个专家层共用第二张卡。来自三到四张卡的机器报告很受欢迎
（见[社区](../community.md)）。

## 多张卡一起做什么

两张及以上卡时，引擎在启动时为三种机制按"每个 decode 窗口的毫秒数"定价：依据各卡的内存带宽、VRAM 和模型大小，并打印一行，
例如 `multi-gpu: 2 cards unlike; ms per window: expert tier 7.9, layer split 13.5, tensor parallel 9.0
(not built); picked expert tier`。每一种多卡设置都会出现这一行，卡是否相同都一样。只有一张卡时（未设置，或只给一个编号）没有
选择：什么都不定价，也不会使用其他卡，甚至不会让它们对该进程可见。

- **专家层**：主卡运行每一层，其他卡持有并计算专家（见上）。
- **层拆分**：每张卡依次运行一组层。切分在启动时、放置任何权重之前搜索，每张卡只持有自己那些层的稠密权重，所以它的 VRAM 像
  专家层那样用于专家。每张卡在自己的设备上规划自己那些层的专家，如同一张卡时那样，窗口交接给下一张卡一次，代价是每个窗口的固定
  一部分。drafter 留在第一张卡上并读取每个窗口最后一卡的行；最后一卡持有 head。没有卡持有的专家从所有阶段共享的一份 pinned RAM
  副本读取（常驻 RAM 模式，与专家层相同），每张卡的自适应换入换出只在自己那些层内进行。
- **相同卡的层拆分，窗口重叠**：两张卡、一个服务器加 drafter、一次一个会话时，拆分还会让相邻窗口重叠。第一张卡以"K 被整体
  接受"的猜测开始第 K+1 个窗口，而第二张卡仍在校验 K。猜测成立就立刻推进 K+1；失败则回滚第一张卡的状态并重跑该窗口，所以两种
  情况的文本相同。拆分的价格不计重叠。引擎日志按请求打印 `pipelined windows: N launched, M held`。
- **张量并行**：每一层都跨卡拆分。只定价、未实现：稠密部分占一个窗口字节的三分之一，所以两张卡之间拆它只能省约 2 ms，而卡之间
  的交换（经主机 staging，每 10 KiB 约 5.4 us）代价差不多；专家层已经共享了专家。

只有匹配的卡（内存带宽和 VRAM 相差 10% 以内）才能选专家层以外的机制，而且只有当它比专家层便宜至少 5% 时才行。不同的卡总是使用
专家层。价格是对实测窗口拟合的估计（一块 RTX 5090 配一块 RTX 5060 Ti：专家层 7.9 ms，试过的切分上普通层拆分实测 13.4-13.7 ms；
两块 RTX 5080：报告 147 tok/s，定价 141），适合用来做选择，不适合用来预测速率。

## 跨卡的长提示词

在专家层下，当没有其他会话在解码时（使用 `--parallel` 时是当其他所有槽位都空闲时），长的新增提示词部分会作为主卡与各专家层卡之上
的流水线来读取。主卡读每个块的开头那些层并交出去；每张专家层卡在前面的卡读下一个块时读下一组层。最后一个块靠后的层由主卡自己读。

- **内存：** 专家层卡的权重（来自启动时制作的 pinned RAM 副本）、提示词状态和缓冲在读取期间放入它那层的最后几个槽位，所以在提示词
  之外各层持有的内容不变，decode 也不受影响。超出可借槽位的提示词在主卡上读取。
- **选择：** 引擎把"只用主卡"与每一种阶段数、每一种切分组合比较定价，依据是每张卡的内存带宽、探测到的链路速率和每张卡持有的专家，
  只有在便宜至少 5% 时才拆分。专家层卡按内存带宽顺序加入，最快的那张读最后那些层。启动行和请求行以 `prompt split:` 开头并打印价格，
  并说明某个部分为什么留在主卡。
- **留在主卡：** 单个块中的一部分（最多 32,768 个 token）；有更慢的专家层卡时，短到只走路由的块；卡匹配时，4,096 个 token 以下的块；
  在其他槽位解码时到达的提示词。
- **三张及以上卡：** 当它们全都匹配（内存带宽和 VRAM 相差 10% 以内）时运行。卡不同时关闭，启动行会打印它本来的代价。
- **每一种专家格式** 都按 pack 自己每层的专家字节定价。可借槽位装不下主卡的块时（GGUF 专家格式的提示词缓冲比 NVFP4 的大），专家层卡
  读更短的块，启动时打印 `prompt split: chunks of at most N tokens fit the tier cards' slots`。
- **关闭条件：** `--peer-exclusive`；没有专家的 RAM 副本；使用控制向量；RAM 或某一层的槽位紧张；上下文短到拆分不划算（启动行会说明）；
  或者专家层卡在自己的阶段之外保留不足 256 MiB 空闲（`peer-reserve-mib` 设置这部分空间）。
- **读取期间到达的更短请求** 在主卡当前块结束时获得执行机会。

## 两张 16 GB 卡

`gpu "0,1"` 配两张 16 GB 的卡（比如两块 RTX 5080）运行专家层：每张卡用自己剩下的 VRAM 持有专家，第二张卡还读取它那些专家在每个
提示词中的份额。引擎给第二张卡的层定容时，为这部分份额的缓冲留出空间（约 200 MiB，这个大小是算出来的，不是设置项），并再多留
`peer-reserve-mib`（默认 600 MiB；至少 128）供该卡在专家就位后需要的其他一切使用。如果启动时打印
`prefill peer: the peer's buffers do not fit`，就调高 `peer-reserve-mib`（那张卡在驱动显示器或其他程序占用了它的 VRAM），第二张卡的
专家会按相同数量减少。启动行 `peer GPU 1: N experts` 说明它持有多少。
