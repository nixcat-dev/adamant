# GPU

[English](../../configuration/gpus.md)

一个设置决定用哪些卡：`gpu`。它在服务器里（配置文件 `server` 段的 `"gpu"`，或 `--gpu`）、在 `basalt` 本身、在 `basalt-bench` 和 `basalt-probe` 中含义相同。

| 取值 | 使用的卡 | 主卡 |
| --- | --- | --- |
| 不设置 | 仅 GPU 0；启动时一条警告点名其他可见卡 | GPU 0 |
| `"0,1"`、`"1,0"` 等 | 恰好这些卡，按给定顺序 | 列出的第一块 |
| `"auto"` | 每一块可见的 Ada（sm_89）卡；其他卡被跳过并打印一行点名 | 内存带宽最高者，其次 VRAM 最多者 |

卡的编号方式与 `nvidia-smi` 一致。设置了 `CUDA_VISIBLE_DEVICES` 时，编号在其列表内计数（`CUDA_VISIBLE_DEVICES=1,0` 让 `gpu 0` 成为 `nvidia-smi` 眼中的 1 号卡），并且其中的编号也按 `nvidia-smi` 的编号理解。超出可见卡范围的编号、重复列出的卡，或不是 Ada（sm_89）的卡，都会以错误终止启动。

主卡存放 dense 权重、KV cache、drafter 和自己的专家缓存。引擎决定其余卡的职责，并在启动时打印一行，例如 `gpus: RTX 5090 (nvidia-smi 0) main, RTX 5060 Ti (nvidia-smi 1) expert tier`：

- **专家层。** 主卡之后的每块卡存放主卡没有的专家，在每个 decode 窗口计算它们的行，并像主卡的缓存一样跟随会话。专家按热度从高到低分配，每个给到按其内存带宽计迄今工作量最少的层，直到每一层都放满。双卡时，速度不低于主卡的第二块卡还会拿走最热专家的一份，于是两卡在每一层都计算被路由专家；更慢的第二块卡接主卡之后的专家。每一层都用主卡的 kernel 计算自己的专家，所以专家位于何处不改变它的行。第二块卡还计算每个提示词分块中其专家的份额：它与主卡一样快时是任意分块，更慢时只到 2,559 行的分块（更慢的卡在更长分块上多付的代价，超过它替主卡链路省下的专家）。当它的内存比主卡更快时，它还接管每个 GDN mixer 和输出头的一份（各有一行启动日志；见 [GDN 分割](../precision/gdn-split.md)）。
- **空闲。** 引擎最多运行三个专家层：第五块及之后的卡保持空闲。

三块及以上的卡属于社区验证范围：这条路径在这里只在双卡上检查过，由两个专家层共享第二块卡。欢迎三卡或四卡机器的报告（见[社区实测](../community.md)）。

## 多卡协同

两块及以上的卡时，引擎在启动时按每 decode 窗口的毫秒数为三种机制定价——依据各卡的内存带宽、VRAM 和模型大小——并打印一行，例如
`multi-gpu: 2 cards unlike; ms per window: expert tier 7.9, layer split 13.5, tensor parallel 9.0
(not built); picked expert tier`。无论卡是否相同，每个多卡设置都会出现这一行。只有一块卡时（不设置，或只有一个编号）没有选择：什么都不定价，其他卡既不被使用，进程甚至看不到它们。

- **专家层**：主卡运行所有层，其余卡存放并计算专家（见上文）。
- **层分割**：每块卡顺序运行一个层块。切分点在启动时、任何权重放置之前搜索，且每块卡只存放自己那些层的 dense 权重，所以其 VRAM 与专家层方案一样留给专家。每块卡像单卡一样在自己的设备上规划其层的专家，窗口被完整移交下一块卡一次，这占窗口的固定一部分。drafter 留在第一块卡上，读取最后一块卡每个窗口的行；最后一块卡持有输出头。没有任何卡持有的专家从一份所有阶段共享的锁页 RAM 副本读取（常驻 RAM 模式，与专家层方案相同），且每块卡的自适应换入始终限于自己的层。
- **相同卡的层分割、窗口重叠**：两块卡、一个服务器、带 drafter、一次一个会话时，层分割还会重叠相邻窗口。第一块卡服务完窗口 K、且 drafter 的链已持有越过 K 的草稿时，第一块卡就好像每一行都被保留一样提交 K，并从"K 会被整体接受"的猜测开始运行窗口 K+1，而第二块卡此时仍在验证 K。猜中了，K+1 立即送交第二块卡；猜错了，第一块卡回滚状态并重跑该窗口，所以两种情况下文本相同。层分割的定价不含这一重叠。引擎日志每请求打印 `pipelined windows: N launched, M held`。
- **张量并行**：每一层都切分到各卡。它只有定价、没有实现：dense 部分占一个窗口字节的三分之一，因此两块卡之间切分只能省约 2 ms，而卡之间的交换（经宿主中转，约每 10 KiB 5.4 us）花费与之相当；专家层机制已经在共享专家了。

只有匹配的卡（内存带宽和 VRAM 差距在 10% 以内）才可以选择专家层之外的机制，且只有当定价比专家层低至少 5% 时。不匹配的卡总是用专家层。这些定价是拟合实测窗口的估计值（5090 配 5060 Ti：专家层 7.9 ms，在尝试过的切分点上实测普通层分割 13.4-13.7 ms；两块 5080：报告 147 tok/s，对定价 141），可用于做选择，不能用于预测速率。

## 跨卡读取长提示词

在专家层方案中，当没有其他会话在 decode 时（启用 `--parallel` 时，当所有其他槽位空闲时），一段很长的新提示词可以作为跨过主卡与各层卡的流水线来读取。主卡读取每个分块的前几层并移交分块；每张层卡接着读取它的下一个层块，而其前面的卡已在读取后面的分块，最后一张层卡读到最后一层为止。当各层卡交还其层的状态并取回自己的专家后，主卡自己读取最后一个分块的后续层。层卡的权重、提示词状态和缓冲区在读入期间放入该层的最后几个槽位（其权重来自启动时制作的锁页 RAM 副本），因此在提示词之外，各层保持原有内容，decode 不受影响。引擎分别按"全部留在主卡"和"任意级数、任意切分"为每一段定价——依据每块卡的内存带宽、探测到的链路速率（单独探测每块卡，以及所有卡同时探测，共享交换机或 RAM 可能使总量低于各自之和）以及每块卡持有的专家——只有当跨卡至少便宜 5% 时才跨卡读取。层卡按内存带宽顺序加入，最快的读最后的层。启动时，每块卡按提示词为上下文长度（最高 131,072 token）值得的级数分到一些层，再多给几层。启动行和请求行以 `prompt split:` 开头并打印定价；留在主卡上、超过一个分块的段会说明原因（`prompt split: N tokens read on CUDA0 (...)`）。分块是主卡自己的分块，所以一个分块的一部分（至多 32,768 token）留在主卡。提示词最后若干个 cell 的草稿层行经移交缓冲区从最后一块卡带回（最后两个移交的分块原路带回，更早的越过所在分块双向带回），所以深提示词的较小分块——其 KV 让主卡能借出的槽位更少——仍能参与分割。对更慢的层卡，短到可以在主卡的一次读取中只走 routed、由该卡计算其专家行的分块，会留在主卡（分割反而让出这部分）；卡匹配时，4,096 token 以下的分块如此。三块及以上的卡全部匹配（内存带宽和 VRAM 差距在 10% 以内）时才运行；三块及以上不匹配的卡时它保持关闭，直到在这样的配置上测量过，启动行会打印其预估成本。以下情况关闭：`--peer-exclusive`、没有专家的 RAM 副本、控制向量、NVFP4 之外的专家（定价按其拟合）、RAM 或某层的槽位不足、或某张层卡在其阶段之外保持不到 256 MiB 空闲（读取会把它的 kernel 加载到那里；`peer-reserve-mib` 决定留多少）。一切随提示词增长的东西都在借出的槽位里，所以放不下这些槽位的更长提示词在主卡上读取。其他槽位正在 decode 时到达的提示词像以前一样在主卡上并行读取。跨卡读取期间到达的短得多的请求会在主卡当前分块结束时获得处理：主卡自己读取该分块的后续层，提示词剩余部分稍后读取，与主卡读取时的处理相同。

## 两张 16 GB 显卡

两块 16 GB 的卡（比如两块 RTX 5080）用 `gpu "0,1"` 运行专家层：每块卡在 VRAM 剩余空间里存放专家，第二块卡还读取每个提示词中其专家的份额。引擎会控制第二块卡的层大小，为该份额的缓冲区（约 200 MiB，大小是计算出来的，不是设置项）和额外的 `peer-reserve-mib`（默认 600 MiB；至少 128）留出空间，供该卡在专家就位后所需的一切使用。如果启动打印
`prefill peer: the peer's buffers do not fit`，就调高 `peer-reserve-mib`（这块卡显示有显示器或其他程序在用其 VRAM），第二块卡的专家相应缩小同样的量。启动行 `peer GPU 1: N experts` 说明它容纳了多少专家。

## 引擎日志

服务器把引擎的输出——引擎在启动时和运行中打印的 `basalt ...` 行——写到 `~/.cache/basalt/<id>/engine.log`，每个模型文件一个文件夹（`<id>` 取自模型文件的 16 位十六进制数）。引擎启动失败时，`[server] engine log: PATH` 会指明该路径。`[server]` 行是服务器自己的，输出到它的终端。
