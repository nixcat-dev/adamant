# 图像来源

[English](../../configuration/image-sources.md)

请求以 `data:` URL、`http(s)` URL、`file:` URL 或路径来指代一张图像。服务器为它读取什么，取决于请求来自哪里。这对请求中任何位置的图像都成立，工具结果也不例外。

| 来源 | 来自本机 | 来自其他任何地方 |
| --- | --- | --- |
| `data:` URL | 可以 | 可以 |
| `http(s)` URL | 可以，任意 host，跟随重定向 | 仅限用 `--image-url-host` 点名的 host，拒绝重定向 |
| 路径或 `file:` URL | 可以，服务器用户可读的任意文件 | 仅限 `--image-dir` 点名目录之下 |

所有来源、所有客户端：单张图至多 32 MiB 字节、64 megapixels，一次读取至多 60 s，且只读常规文件（不读 FIFO 或设备）。一个请求的所有图像作为文件合计至多 1 GiB（在任何 PNG 转换之后）。等待编码的已读图像超过 2 GiB 时，请求得到 409，可以稍后重试。

## 什么算本机

由套接字的对端地址决定：它必须是回环地址。本机自己的局域网地址属于另一台机器。请求头只能往坏处改。回环请求带有以下内容时仍算远程：

- 转发头（`Forwarded`、`X-Forwarded-*`、`X-Real-IP`、`Via`、`CF-*`、`Tailscale-*` 及类似项），
- 不是 `localhost`、回环地址或 `0.0.0.0` 的 `Host`，例如客户端通过名称访问本机，
- 任何 `Origin`，或不是 `none` 的 `Sec-Fetch-Site`：每个网页都算，包括服务器自己的页面、另一个本地端口上的页面、被 `--cors-origin` 放进来的页面，以及桌面应用的页面（`app://`、`file://`）。桌面应用的主进程算本地；它的页面发送 `data:` URL，
- 服务器无法解析的请求头。

`--image-remote-only` 让每个请求都算远程，无论对端是谁。

因此被拒绝的请求会得到一个 400，说明这是策略拒绝、原因，以及哪个标志允许它。

## `--image-url-host HOST[:PORT]`

恰好这个 host：不含子域、不含通配符，除非给出端口，否则 `http`/`https` 用各自默认端口。

- 一个**域名**必须只解析到公网地址。回环、私有、link-local（包括云 metadata）、CGNAT、组播和保留地址一律拒绝；IPv6 仅允许全局单播，不接受 IPv4 映射、NAT64 或 6to4 形式。连接
  使用被校验过的那个地址，`Host`、TLS 名称和证书校验仍用原始域名。
- 一个 **IP 地址**按字面接受，包括私有地址：`--image-url-host 192.168.1.20:8000`。这是放行网络内一台机器的方法。像 `localhost` 或 `nas.lan` 这样解析到私有地址的名字不通过。

这些抓取不使用环境代理设置。环境代理是给来自本机的请求用的。

## `--image-dir DIR`

路径必须是绝对路径，并且在经过符号链接和 `..` 解析之后仍位于 `DIR` 之下——无论它以何种方式到达那里——且打开的就是解析后的文件。`DIR` 之外的东西一律不打开，尽管解析路径会读取沿途的链接。
在 Linux 上它逐组件打开，因此打开过程中换成符号链接会被拒绝。在 Windows 上，打开后的文件会与路径做事后核对，且 UNC 与设备路径、`C:relative` 形式的路径、备用数据流和保留名（`CON`、`NUL` 等）被拒绝。`DIR` 内部的硬链接或 bind mount 仍算 `DIR` 内部。

在 `DIR` 之外，以及其中缺失、不可读或非常规文件的名字，拒绝信息完全相同。
`DIR` 内一个可读的文件可能给出不同回应：过大，或不是图像。

## 限制

- **本机的转发器。** 本机上任何把别人的请求转手传下去的东西，除非它添加转发头，否则都会让它们看起来是本地请求，而 `Host` 帮不上忙：`proxy_set_header Host $host` 原样透传客户端发来的值，比如 `localhost`。这包括：
  - 默认配置的 nginx（不添加转发头）和不带 `option forwardfor` 的 HAProxy，
  - 纯 TCP 转发器：`ssh -L`、`socat`、`kubectl port-forward`、从宿主回环发起的 rootless `pasta`，
  - 把用户的 `image_url` 传下去的应用网关：LiteLLM、Open WebUI 的 API。

  能连上其中任何一个的人，就能读取服务器用户的文件和它的网络。这样的服务器要设 `--image-remote-only`。Caddy、Apache、Traefik 和 `tailscale serve` 会添加转发头。
- **共享机器。** 来自本机的请求以服务器的用户身份读文件，而不是以客户端的用户身份。另一个本地用户可获得同样的能力，因此在那里要设 `--api-key`；回环请求和其他请求一样需要 key。持有 key 的人，在本机上，就拥有这一能力。除 key 之外不分本地用户彼此。
- **容器。** 已发布端口的对端是网桥的网关，所以容器的客户端都算远程，包括宿主上的客户端；请用 `data:` URL 或那两个标志。路径指的是容器内的文件。用 `--network host` 时对端才是真实的。
