# 0.3.0

2026-11-05. Build from source: [building](../building.md). The config format changes, so read [Upgrading](#upgrading) first.
The `.basalt` format stays version 2.

## Highlights

- A model adapter: a model's own code lives in its own folder (`src/models/<model>`), shared code sees a model only through the
  adapter, and the engine registers the models it has. To add one: [adding a model](../adding-a-model.md).
- A router: a config lists several entries naming one pack each, a request's `model` field picks one, and one is loaded at a time.
  Clients wait through a swap; a wrong name is a 404 and a failed load a 503 naming the model, and the server stays up.
  [models and the router](../configuration/models.md)
- The config file's v2 shape: a `models` list, a shared `engine` block and a `server` block.

## Upgrading

1. Rebuild: [building](../building.md). The Linux build needs GCC 13 or newer.
2. **The config format changes.** A config without `models` is refused at start: `Basalt requires v2 config, please upgrade`.
   `python3 tools/migrations/config_v1_to_v2.py basalt_config.json -o basalt_config.v2.json` writes the new shape; the old file is
   left as it is. [migration](../configuration/models.md)
3. `.basalt` files keep working as they are.
4. Open pull requests need a rebase: most of `src/core`, `src/prefill`, `src/kernels` and `src/program` moved. Model code is under
   `src/models/<model>` and `include/basalt/models/<model>`, and server dialects under `serve/models`.
   To add a model: [adding a model](../adding-a-model.md).

## Recent

Changes since 0.2.1.

### New

- One server loop serves every configured model, and `/health`, `/metrics` and `/v1/status` report swaps and each model;
  `/v1/models` lists every configured entry with its status.
- The stats page's header is a model picker: choosing a model loads it, and the header shows the load's progress.
- `--lazy` keeps `--vision dynamic`, which encodes inside the engine a request loads first; only a sidecar encoder is dropped.
- Images in tool results reach the prompt on every API; what cannot be placed is refused and logged.

### Fixed

- An engine line with broken UTF-8 no longer stops the server's reader thread.
- Grammar: a closing tag with non-ASCII characters parses.
- An idle sleep the engine refused warns once and waits for the next request.
- The first SIGTERM ignores later ones, so the engine's exit and its spill to disk are not cut short.
- `/metrics` reports the GPU on Windows: NVML is read from `nvml.dll`.

### Removed

- `basalt-overlap` and `basalt-concurrent`, and code nothing could reach, among it the naive S2 decode and S2 GEMV kernels and the
  verify window's S2 expert branch.
