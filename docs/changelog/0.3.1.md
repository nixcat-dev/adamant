# 0.3.1

2026-11-08. Basalt's release, merged into this fork; only the paths this fork builds are listed. Build from source: [building](../building.md). Read [Upgrading](#upgrading) first: a few flags change. The `.basalt` format stays version 2; `experts.layout` v7 is a section version.

## Highlights

- One shared prompt path for the peer card (`prefill::PeerShare`): the peer computes its experts' prompt rows from staged group buffers, in the main card's formats and activations, and returns the rows. Ada validation pending.
- New packs: Flash-Next `UD-IQ1_S` (a layer whose gate and up rows differ in type, `experts.layout` v7) and `UD-IQ4_XS`; Q5_K and Q6_K expert layers join the glue path (#264) and IQ4_XS gate/up rows too (#272, @michmill1970); Q2_K and Q3_K experts run on every path.
- The model file is read in place: nothing is unpacked into `~/.cache/basalt`. The engine's `--vision` encodes in the engine and `--vision-external` takes a sidecar's embeddings.
- `--kv-resident` works with `--batch` and `--parallel`: every slot streams its own K/V (#186, @f1zz1ec0ke).
- One RAM reserve (`--ram-reserve-mib`) and one serving RAM guard, and experts on the SSD said everywhere.
- `--max-payload-mib` sets the largest request body.

## Upgrading

1. Rebuild: [building](../building.md).
2. **`--peer-prefill-rows N` is gone.** `--no-peer-prefill` (config key `no-peer-prefill: true`) turns the peer card's prompt share off; it is on otherwise.
3. **The engine's `--vision-mmproj PATH` is gone.** The engine takes `--vision` (encode in the engine, from the pack's `vision/mmproj`) or `--vision-external`. The server's `--vision dynamic|cpu|N` is unchanged and passes them itself.
4. **A pack with `experts.layout` v7 needs 0.3.1.** Only `UD-IQ1_S` has one; older engines refuse it with their update message. Every other pack keeps running on older engines.
5. **Conversations stored on disk miss once**: the cache key changed with the vision flags.
6. **`--ram-reserve-mib` (default 2048) replaces the RAM floors**, and `--ram-reserve-mib 0` turns the guard off. [memory floors](../running.md#memory-floors)
7. `~/.cache/basalt/<id>` keeps only `engine.log` and the conversation cache; an earlier `tokenizer/` folder and `vision/mmproj.gguf` (886 MiB for Flash-Next) can be deleted.

## Memory, start and serving

- **Experts on the SSD are said everywhere.** Any expert only the file holds gives one engine warning: `N experts on SSD (X GiB)
  · free X GiB RAM`, plus the model's other hints. The server console repeats it, `/metrics` carries `engine.spill` (`experts`,
  `total`, `bytes`; `null` when nothing spilled) and each request's `ssd_share`, and the stats page turns its Experts block amber
  with an SSD tier. [memory floors](../running.md#memory-floors)
- **One RAM reserve.** `--ram-reserve-mib` (default 2048) is the RAM left free for the rest of the system; the old floors (a
  percentage of RAM, a fixed late-memory figure, a file-cache minimum) are gone. The prompt and image host buffers are allocated
  first and the RAM tier then takes the free RAM less the reserve and the driver's page tracking, so one place short no longer
  sends whole layers of experts to the file. The prompt ring of second-card and file reads is capped instead of growing with the
  experts left in the file, and a prompt no longer stages a whole chunk's embeddings and Engram rows. The RAM copy allocates its
  checkpoint blocks and holds the RAM of its page-locked prompt buffers before sizing itself; its estimate of what it takes later
  is gone. [memory floors](../running.md#memory-floors)
- **One RAM guard.** The serving RAM guard runs in the shared serve path and holds the reserve, so every model sheds parked
  conversations, holds new requests and stops one at critical RAM alike. `--ram-reserve-mib 0` turns it off, for machines where it
  stopped requests that would have fit. [memory floors](../running.md#memory-floors)
- **Default context 8,192.** Flash-Next's was 4,096; `--max-context` still sets it. [models](../models/index.md)
- **Start lines.** Each entry's line shows the drafting the engine will run (`spec=N`); a shared idle sleep is said once, on the
  shared line; the conversation folder line shows only with `--debug`; a load reads `loading MODEL (N waiting)` and a swap
  `swap OLD -> NEW (N waiting)`.
- **`--max-payload-mib` sets the largest request body.** The server reads up to 256 MiB by default; a bigger body gets a 413
  naming the limit. [configuration](../configuration/index.md)

## Flash-Next

- **Packs:** `UD-IQ1_S` converts as shipped (a layer has IQ2_S gate and IQ2_XXS up rows) and `UD-IQ4_XS` is on Hugging Face; the
  Unsloth `UD-IQ1_M`, `UD-IQ2_XS` and `UD-IQ3_XXS` packs join the published set. [Flash-Next](../models/qwen38-flash-next.md)
- **Experts:** Q5_0 down layers run on MMQ prefill and the device-planned tail; Q2_K and Q3_K tiles, grouped kernels and CPU dots;
  IQ4_XS and Q5_K/Q6_K gate/up rows join the glue kernel.
- **`--no-peer-prefill`** replaces `--peer-prefill-rows`; the peer card's prompt share runs on the shared `prefill::PeerShare` path.
  [Ada](../precision/ada.md)

## Fixed

- A dead engine is reported by its exit code or signal and its last error line, not a guessed cause.
- Engine protocol lines are written whole, so a progress line no longer lands inside a token line.
- `/metrics` keeps the last context while a start is under way; the stats page shows a single slot's context.
- The telemetry thread stops when the router stops or the server closes.
- A request with images no longer scans their base64 for literal tags.
- The auto line names the resident amount as `ram-experts`; `--model` with a config file says it is not supported.

## Checked

Run on the commits that changed the code, on Basalt's hardware; the same paths are open for Ada measurement
([Ada](../precision/ada.md)):

- Kernel changes: greedy output identical to the build before (frozen tiers, 400 tokens, struct and prose).
- `UD-IQ1_S`, 100 chunks, int8 KV: measured through the decode path against the BF16 reference ([method](../precision/quality.md)).
- Flash-Next NVFP4 with the shared peer path: greedy identical, peer tier pinned.
- `prefill::PeerShare` and the mixed gate/up layers are meant to be bitwise equal to the paths they replace; their parity checks
  cover the bytes, not the Ada kernels.
