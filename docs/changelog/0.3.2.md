# 0.3.2

2026-11-08. Basalt's release, merged into this fork; only the paths this fork builds are listed. Build from source: [building](../building.md). No flag changes; the `.basalt` format stays version 2.

## Highlights

- A clean Release build is much faster: Flash-Next's `dec_moe.cu` is split so the peer kernel's four variants compile in parallel, and `tools/check_cu_includes.sh` keeps a `.cu` from including another. The GPU code is the same except those four variants, which ptxas schedules slightly differently. Ada timing and greedy-identity check pending.
- `tools/package_release.py` packs a built tree into a Linux x64 or Windows x64 archive. It holds no CUDA libraries: the CUDA 13 toolkit's runtime and an R580 or newer driver are required. [platforms](../platforms.md#release-archives)
- The binary finds its data, `serve/` and `.venv` next to its own `bin/` folder, not at the source path baked in at build time, so an install can be moved.
- A RAM tier that leaves experts in the file keeps the OS file cache its floor again, so a machine the model does not fit no longer swaps itself unresponsive while loading (#285, @tddgit). [memory floors](../running.md#memory-floors)

## Memory, start and serving

- **The file cache keeps its floor.** 0.3.1 sized every RAM tier to the free RAM less `--ram-reserve-mib`, so where the model does not fit, the page-locked tier left the file reads and the rest of the system about 2 GiB and the load never finished (reported by @tddgit, #285). A tier that leaves experts in the file now also leaves the file cache what it needed before 0.3.1 (every expert of the largest layer, a prompt chunk's reads, at least 4 GiB); a tier that holds every expert is sized as before, and a given `--resident-budget-gib` is not cut. The start line counts the floor.
- **The RAM top-up reads the container's limit.** After the load it sized itself from `/proc/meminfo` alone and pinned experts past a cgroup limit; it reads the same container-aware figure as the plan and the copy.
- **The engine refuses to start without its expert profiles.** A binary run away from its install folder found no `data/profiles` and fell back silently. The start now stops before loading weights, naming the missing profile and that `data/` must sit next to `bin/`; `--expert-profile` still replaces the main profile.
- **A failed free-memory query says why.** The call, the error and the card are in the message instead of an unrelated copy failure later (@easonLiangWorldedtech, #289).
- **The Experts card shows an all-VRAM box as all VRAM.** With every expert resident the card stayed at "-"; `/metrics` carries `expert_total` and the card draws a full VRAM bar, "All in VRAM" (@beastrobin, #287).

## Kernels

- **Q6_K short rows** stage their columns once per block.
- **The exact AVX-512 CPU expert rows** (IQ1_S, IQ2_XXS, IQ2_XS, IQ1_M) decode a block once for up to four tokens.
- Both are numerically neutral: the same sums in the same order. Ada greedy-identity check pending.

## Release archives and install

- `tools/package_release.py` packs `bin/`, `serve/`, `data/`, `docs/` and what the server imports into `basalt-vX.Y.Z-linux-x64.tar.gz` or `basalt-vX.Y.Z-windows-x64.zip`.
- `bin/basalt serve` uses the `.venv` at the archive's top directory when it is there. The build-time source path (`BASALT_SOURCE_DIR`) is gone: the install root is the directory above the executable's own.
